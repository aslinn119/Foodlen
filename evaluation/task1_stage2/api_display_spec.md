# 未来 Web 展示所需字段 草案

这是一份静态设计，供组内后续讨论；当前没有实现接口、网页或部署服务。最终字段应以任务二 Schema、组内模型输出和实际界面需求为准。

## 输入与基本信息

用户上传一张普通 RGB 食物图片；界面显示图片预览。系统内部记录图片标识、文件名和模型版本。上传格式、大小限制及异常处理待开发时确定；上传失败或模型未运行时应显示明确状态。

## 建议的展示内容

| 区域 | 建议字段 | 说明 |
|---|---|---|
| 图片 | `image_id`、`image_url` | 上传图片标识和可访问地址，具体地址规则由实现方确定。 |
| 描述 | `caption`、`caption_model`、`decode` | 展示模型生成的描述、模型版本和解码方法。 |
| 结构化结果 | `items`、`total_weight_g`、`total_calories_kcal`、`protein_g`、`fat_g`、`carbohydrate_g` | `items` 每项包含 `name`、`weight_g`；最终以任务二确定的 Schema 为准。数值和单位都应显示，未计算时为 `null`。 |
| Judge | `input_mode`、`judge_model`、`scores`、`reason`、`status` | 四维评分与简要理由。视觉/文本模式须明确区分；未运行时显示未运行，不能填入假分数。 |
| 注意力 | `tokens`、`attention_images`、`caption_model` | 每个词与对应热图的可访问地址按顺序对齐；无该能力或未生成时显示不可用。 |
| 状态 | `status`、`error_message` | 区分成功、进行中、不可用和失败；显示已实际执行的部分。 |

## 布局草图 文字版

```text
上传图片 → 图片预览
           生成描述与模型信息
           食材和营养信息表
           Judge 评分及依据（明确是否看过图）
           选择生成词 → 查看该词的注意力热图
```

描述、结构化结果、Judge 和热图可以分别成功或失败；一个模块没有结果时，界面应保留其他已完成内容。营养数值是模型预测，是否以及如何使用需由组内确定展示说明。
