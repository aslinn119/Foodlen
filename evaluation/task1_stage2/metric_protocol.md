# Task 1 统一评测协议 初版

版本：2026-10-27，供组长和刘杰确认。此协议复用已有实验的实现，后续 V3/V4 须按同一口径重算；组内若选用其他正式评测工具，应统一重算所有模型并单独标注，不把不同口径的数值直接合并。

## 数据与对齐

- 使用 `inputs/test_annotations.jsonl` 作为固定测试标注，共 4,938 张，每张一条参考描述；文件 SHA-256 在运行结果 JSON 中记录。
- 每个模型提供每张图一条预测；以 `file_name` 完整路径标识对齐。缺失、多余、重复图片或与标注不一致的参考描述会报错，不用不一致的结果作模型对比。
- 小写后按空格切词，标点随原 token 保留；空预测允许并计入分数。每张图只有一条参考描述，结果不应直接与多参考评测比较。
- 同一数据和口径对比；V1/V2 主比较分别使用重训 V1 greedy 与 V2 greedy。Beam-3 是同一 V2 权重上的解码比较，单列显示。

## 三类指标

- BLEU-1 至 BLEU-4：沿用组内 `metrics/bleu.py` 的语料级单参考实现，数值为百分制。其源码注明主要用于训练监控，不能称为已通过官方 COCO 评测器验证的正式分数。
- ROUGE-L：沿用 `metrics/caption_metrics.py`，token 级最长公共子序列 F 分数，β=1.2，逐图平均，数值范围 0–1。
- CIDEr-D：沿用同文件单参考实现，1–4 gram TF-IDF、σ=6 的长度惩罚、最终乘 10；词频统计由本次整个参考集计算。此处标明为本地实现和切词口径，未与官方工具逐项验证。
- 这三类指标各有侧重，不能把 BLEU-1 和 BLEU-4 当成两类指标。对后续各模型使用相同的测试集、预处理和代码。

## 来源及限制

原 V1 历史 BLEU-4 为 4.5702%，来自组长提供的报告记录，缺少对应 checkpoint，不能用它当作本轮严格消融基线，也不能声称已复算。重训 V1 BLEU-4 4.8812% 与 V2 greedy 5.2914%、V2 beam-3 5.3997% 均可从已保存的完整预测重算。

模型选择使用验证集前 500 条 BLEU-4；最终报告的结果来自完整测试集。测试集结果不用来调参；新模型应在提交测试预测前固定权重和解码设置。若组内对单参考和官方指标口径有其他要求，以组内确认后的统一协议重算。

## 输入和运行

在本文件夹运行 `python eval_task1.py`，会读取复制的 V1/V2 预测与标注，并将结果写入 `outputs`。预测 JSON 可以是数组，或包含 `predictions` 数组的对象，每条至少包括字符串 `file_name` 和 `hypothesis`；可带 `reference` 用于一致性检查。结果需覆盖测试集所有图片。

接入其他模型示例：`python eval_task1.py --model "V3=路径/v3.json" --model "V4=路径/v4.json" --output-dir outputs/v3_v4`。不同机器不需要原训练权重即可根据预测计算指标；复现预测则需要模型、相同数据和配置。
