## 后续如何更新

1. 成员将更新交到对应模块，附代码版本、配置、输入、预测、指标、命令和结论；避免再建一个平行“最终最终版”。
2. 替换正式结果前，把上一版移到模块历史区，并更新results入口、模型清单和进度。
3. 新旧V2、原V1与重训V1、新旧Task2 B明确命名；不通过覆盖单个权重合并版本。
4. 不凭目录整理声称复现通过。运行版需另行验证权重、路径、依赖和真实样例链路。
5. 本次复制哈希只对应整理时的快照。后续变更使用版本控制并更新来源记录；不要直接重跑整理脚本覆盖main。
