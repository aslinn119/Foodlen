## 冻结与数据口径

固定使用camera_4.jpg，每场景一张RGB。5,668个校准场景和2,368个评估场景ID无交集。模型未在OmniFood8K上训练、选型或搜索超参数。均值和ResNet18归一化统计固定来自旧训练集，CLIP使用原检查点统计。新接口对点预测统一非负截断；CLIP沿用原接口的一位小数输出。

官方TXT目标作为评估依据；原能量为kJ，统一除以4.184转为kcal。保留26个已发现的标注疑点场景并记录标志，不依据预测好坏删样本或人工改标签。源包与旧提交材料不变。

残差仅取校准集。q为第5103个升序绝对残差，区间为[max(0,p-q),p+q]。calibration.json在评估预测之前保存。目标是每个字段的边际90%覆盖，不是每张图片的条件保证，也不是五项同时90%。

校准版本：`omnifood-abs90-v1-94b7b58711b3`。完整流程计时约182.5秒（不含数据审计和模型初始化）。

## 差异与局限

现有模型在Nutrition5k训练，本次在OmniFood8K上外部评估。均值基线在部分字段优于学习模型，说明原Task2效果不能直接外推到新域。本次不得根据最终评估结果改阈值或选择新的后处理。

| 字段 | 校准集标签均值 | 评估集标签均值 |
|---|---:|---:|
| 总重量 | 195.068 | 207.182 |
| 热量 | 296.611 | 381.864 |
| 蛋白质 | 9.332 | 12.230 |
| 脂肪 | 18.169 | 27.346 |
| 碳水化合物 | 24.644 | 22.942 |

标签均值差异是描述性证据，不足以单独证明欠覆盖原因。官方划分并未提供完整批次来源，组合场景共享基础菜品/营养配方，不能确认交换性或所有观测独立。标准Split Conformal的覆盖结论依赖相应假设，因此这里只报告实际覆盖，不能保证新手机照片或其他数据集同样达到目标。原料数据库计算的标签也不等同于实验室实测营养。

如需后续优化，应另设未使用的开发/训练数据及新的最终评估数据，预先固定方案；当前评估集不得继续被当成调参集。没有进行重训练，并不等于已达到理想预测效果。

## 图片接口与复核

在项目根目录运行：
```powershell
python -m challenge_external.demo_intervals "你的图片路径.jpg" --model clip
```

Python调用：
```python
from challenge_external.runtime import predict_intervals
result = predict_intervals("photo.jpg", model_id="clip")
```

model_id可取mean、resnet18、clip。推理读取模型、固定统计量及校准参数，不读取外部营养标签或根据文件名检索答案。改动被校准依赖文件时拒绝加载旧校准参数。解压包内含推理所需权重和冻结统计量。配置依赖后可离线运行。

verification.json记录独立复算结果：校准排序分位数、15组完整指标、3035条模型/场景欠覆盖记录一致；使用固定首张评估图对三个模型逐一执行图片接口并验证区间。单图与批量GPU计算允许小数舍入容差，不属于样本修正。

主文件：runtime.py（图片接口）、conformal.py（分位数/区间）、run_experiment.py（冻结实验）、verify_results.py（复核）；results/包含版本、预测、指标及案例。run_experiment.py拒绝覆盖已有正式结果。

方法依据：[Split Conformal介绍](https://arxiv.org/abs/2107.07511)；数据来源：[OmniFood8K官方项目](https://yudongjian.github.io/OmniFood8K-food/)。

补充复核：legacy_interface_parity.json 验证同一固定图片上，三个模型的新旧点预测接口五字段完全一致（最大差为0）；本轮外部域结果变差不能归因于该样例的接口迁移差异。
